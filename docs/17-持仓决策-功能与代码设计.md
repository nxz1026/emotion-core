## 0. 术语与口径（先统一，后文只用这些词）

| 词 | 含义 | 反例（不要混用） |
|---|---|---|
| **持仓** | 一笔真实买入：`code + entry_date + entry_price + shares` | 「推荐列表里的一只票」不是持仓 |
| **成本价** `cost` | 该笔的 `entry_price`，**不复权真实成交价** | 后复权价、图上价 |
| **现价** `market_price` | `daily_bar.close`（不复权） | CPT 快照 K 线的后复权 close |
| **raw 域** | 不复权、可直接下单成交的价格域 | — |
| **adj 域** | 后复权价域。**CPT 的 `overlays` 全在 adj 域** | — |
| **倍率** `price_ratio` | `adj ÷ raw`，逐股逐日不同，由 CPT 现算 | 固定常数 |
| **分档** `ladder` | `[{price, pct, shares}]` 的阶梯买/卖量 | 单一价 |
| **建议** `Decision` | 一次决策的完整输出（方向+分档+止损目标+依据） | 信号 `Signal`（那是判定层的事） |
| **判定层** | `algorithms/entry.py`、`algorithms/exit.py`、CPT 状态机 | 本文**一律不改** |
| **包装层** | 本文新增的 `holding_service` 及其下层 | — |

**F6 不变量**（贯穿全文）：缺数**不许**补 0、不许补默认价、不许外推。要么给出标注了来源的数，要么明确 `null` + 原因。

## 1. 范围与已锁决策

### 1.1 做什么

输入 `code + 成本价 + 数量`（可选 `总资金`），输出：

1. **方向**：`ADD`（加仓）/ `HOLD` / `TRIM`（减仓）/ `EXIT`（清仓）
2. **分档价 + 分档数量**：买/卖各自的阶梯（价、占比、股数）
3. **止损价 + 目标价**（带来源标签）
4. **依据**：复用赔率栈与 CPT 的结构事实，逐条可审计
5. **降级说明**：任何一环缺失时，明确说缺什么、用了什么兜底

### 1.2 已锁决策（2026-10-13 奎爷拍板）

| # | 决策 | 取值 | 备注 |
|---|---|---|---|
| **D1** | 数量口径 | **固定风险 + 流动性上限，取小** | 另加单票上限，见 §6.3 |
| **D2** | 总资金 | **可选传**；不传则只给比例，不给股数，**不阻塞** | |
| **D3** | 止损 / 目标 | **结构位优先 + 固定百分比兜底** | 结构位缺失时**标注兜底**，不静默 |
| **D4** | CPT 依赖时机 | **v1 就接 CPT HTTP** | 契约见 §4.2、风险见 §10.1 |
| **D5** | 落库 | **复用 `position` 表 + 新增 `holding_decision` 表** | 表结构见 §3.2 |
| **D6** | 交付形态 | **CLI + HTTP 先行，再上现有 `/stock/<code>` 页** | 不做独立 `/holding` 页 |
| **D7** | 冲突裁决 | **本轮不动**，两侧信号**并排展示** | CPT 契约 §5 / ADR 0001 D4 均写「不设计」 |
| **D8** | CPT `recommendation` 的写副作用 | **接受**，v1 就用它拿 `price_ratio` | 稳态约每心跳每标的 1 行到 `cpt_recommendation`（CPT 自己的 GET 行为，已内容去重+心跳）；`--no-cpt`/`cpt=0` 可临时关 |
| **D9** | 科创板取整 | **接受 `lot=200` 向下取整的近似** | 真实规则是「≥200 起 + 1 股递增」；偏保守。已在 §6.3 标注为已知近似 |

### 1.3 明确不做（写进代码注释与文档，防止后续跑偏）

- ❌ **不自动下单**。只输出建议，`exec_hint` 语义沿用现有契约（见 §7.4）。
- ❌ **不改判定层**：`entry.py` 五条件、`exit.py` 退潮/断板、CPT 一买一卖状态机，一行不动。
- ❌ **不做冲突裁决**（D7）。两侧结论并排给，冲突由人判断。
- ❌ **不 import CPT**（两侧契约明令零代码依赖），只走 HTTP 127.0.0.1:8010。
- ❌ **不给 `CONFIG` 加字段**。`utils/config.py:16` 是 `@dataclass(frozen=True)`，`config_hash()`(:104)
  被 `pipeline_state` / `signal` / `eval_result` 当作策略指纹 ⇒ 新增字段会**让全库指纹换代**。
  本设计的全部常量放**模块级 `Final`**（见 §8.2）。
- ❌ **不写 CPT 的表**。只允许「只读」与「CPT 自己在响应 GET 时写它自己的表」（§4.2 已披露）。
- ❌ **不做历史回填**：决策是按日快照，历史某日的决策不可重算（缺当日输入时就是缺）。

### 3.2 新增表：`holding_decision`（决策快照）

设计原则：**一行 = 某交易日 · 某标的的一次决策**。当日重算 = `ON CONFLICT DO UPDATE` 覆盖（幂等）；
跨日保留即为决策历史，供复盘「当时为什么这么给」。

```sql
CREATE TABLE IF NOT EXISTS holding_decision (
    id               bigserial PRIMARY KEY,
    trade_date       date        NOT NULL,
    code             text        NOT NULL,
    -- 输入快照（当时你告诉系统什么；成本/数量可空 = 只做「未持仓」评估）
    cost_price       numeric(12,3),
    shares           integer,
    -- 市况
    market_price     numeric(12,3),
    pnl_pct          double precision,
    -- 结论
    action           text        NOT NULL
                     CHECK (action IN ('ADD','HOLD','TRIM','EXIT')),
    action_label     text        NOT NULL,
    sizing_method    text        NOT NULL,          -- risk+liquidity | liquidity_only | none
    suggested_shares integer,                        -- NULL = 未给总资金（D2）
    position_pct     double precision,               -- 建议仓位占总资金比；无总资金时用风险反推
    suggested_amount numeric(18,2),                  -- suggested_shares × price
    -- 价位
    buy_reference    numeric(12,3),
    stop_price       numeric(12,3),
    target_price     numeric(12,3),
    price_basis      text        NOT NULL,           -- cpt_structure | pct_fallback
    -- 结构化明细（jsonb，避免为可变长度结构建子表）
    ladder           jsonb       NOT NULL DEFAULT '[]'::jsonb,
    reasons          jsonb       NOT NULL DEFAULT '[]'::jsonb,
    facts            jsonb       NOT NULL DEFAULT '{}'::jsonb,
    inputs           jsonb       NOT NULL DEFAULT '{}'::jsonb,
    cpt_status       text,                           -- CPT 的 status 原样存（并排展示，D7）
    created_at       timestamptz NOT NULL DEFAULT now(),
    UNIQUE (trade_date, code)
);

CREATE INDEX IF NOT EXISTS idx_holding_decision_code_date
    ON holding_decision (code, trade_date DESC);
```

**落点**：`src/emotion_core/data/schema.py` 的 `DDL` 字典末尾（`ref_rs` 之后）。
**索引**加进同文件的 `_INDEXES` 元组。

> ⚠️ **必跑提醒**：`schema.create_all(conn)` 在 `src` 里**没有调用方**，新增表后必须
> **手动跑一次**，否则 DDL 与库内静默漂移（2026-10-13 补建 6 张表即此故）。验收命令见 §9.S1。

## 4. CPT 接口契约（v1 实接，D4；全部 2026-10-13 实测）

### 4.1 只从本机直连 `127.0.0.1:8010`，**不走 nginx**

`ss -ltn` 实测 `127.0.0.1:8010 LISTEN`（pid 160105）。nginx 的 `/cpt/api/` 挂了 `auth_basic`，
**本机直连绕过 basic auth**（这也是本设计的边界：只允许回环地址，不配远端）。

### 4.2 两个端点、各自的写副作用、用途

| 端点 | 用途 | 是否写库 | 结论 |
|---|---|---|---|
| `GET /api/dashboard/a-share/snapshot?code=<6位>` | 取 `overlays{fractals,bis,zhongshus,trend_types}`（**adj 域**）+ `candles` + `signal` + `data_quality` | **默认只读**（`a_share_routes.py:142` 的 R59 修复：`ensure_factors` 默认 `None`，只有环境变量 `CPT_ASHARE_ONDEMAND_FACTOR` 显式开启或 `?ensure_factors=1` 才联网补因子并写库） | ✅ **作为主取数口** |
| `GET /api/dashboard/a-share/recommendation?code=<6位>[&level=&history_days=]` | 取 `action / status / divergence_status / reason / price`（CPT 结论原样，D7 并排展示）+ **`price_ratio`** | ⚠️ **会写**：`a_share_routes.py:270` 每次 GET 调 `_persist_recommendation`；`:362 _should_persist_recommendation` 做了**内容去重 + 心跳**（同内容同 (code,level) 在一个心跳窗口内不重复写，`:393` 的 docstring 说 R59 加的）⇒ 稳态约「每心跳每标的 1 行」到 `cpt_recommendation` | ⚠️ **可用，但必须在文档/日志里披露**；提供 `--no-cpt-recommendation` 开关可关（§8.2） |

**明确不用**：`GET /api/dashboard/track/{code}/advice` —— 它**要求该票在 `cpt_track` 里**（否则 404，
`track_api.py:308` docstring「用户没追踪这票 → 404」），且**每次调用都写一条 `cpt_track_snapshot`**
（`:313`「advice 端点触发即写」）。它需要先改 CPT 的用户数据，不适合当取数口。

```jsonc
  "overlays": {

    "bis":        [ {"direction": -1, "high": …, "low": …, "start_time":…, "end_time":…} ],

    "trend_types":[ … ]
```

**`data_quality` 的两种形状（实测，**不能只看 `degraded`**）**：

| 票 | `data_quality` |
|---|---|
| `001381`（未上市） | `{"degraded": true, "reason": "no_data"}`，`bar_count=0`，`overlays` 四数组全空 |
| `601811` / `000016`（可用） | **没有 `degraded` 键**；而是 `{"severity":"ok"\|"gap", "gap":bool, "gap_count":int, "stale":bool, "closed_bar_count":int, "expected_trade_days":int, "gaps":[…], "unclosed_bar_count":int, "out_of_order_count":int, "ashare_tags":{…}}` |

实测 `000016` 是 `severity="gap"` / `gap_count=5`（停牌期间缺 5 个交易日，
`closed_bar_count=92` vs `expected_trade_days=97`）—— 它**没有** `degraded`，
只判 `degraded` 会漏报这种「有缺口但还能算」的票。

> ⚠️ **降级快照判别**（`cpt_client.overlay_usable`）：`data_quality.degraded == true` 或
> `overlays` 四数组全空 ⇒ **当作无结构数据**，走 §6.2 兜底，**不得**把它当成「结构位是 0/空」。
>
> `cpt_client.data_quality_note()` 把上面两种形状收敛成一句人读提示（正常 → `None`），
> 由 `holding_service` 放进 `reasons[kind="degrade"]`（S4 落地）。

### 4.4 `recommendation` 的响应形状（实测键）

```jsonc
{
  "available": true, "action": "watch", "action_label": "关注",
  "headline": "…", "reason": "…", "price": 21.3,
  "status": "structure_ready", "signal_type": "first_buy",
  "divergence_status": "not_checked", "data_quality": {…},
  "disclaimer": "结构状态翻译，非投资建议",
  "raw_close": 21.3,          // 不复权可成交价（a_share_routes.py:226）
  "price_ratio": 7.0605,      // 可能为 null！见下
  "history": {…}, "level": ""
}
```

**`price_ratio` 的语义与失效条件**（`a_share_routes.py:230-258` 逐字）：
`price_ratio = round(快照最后一根 K 线 close ÷ 同日 daily_bar raw close, 4)`。
它要求**分子分母同一天**；快照会**拒绝缺因子的那一天**（不填 1.0），所以判不出同日时
**`price_ratio = null`**（「绝不给一个看着像真的错数」）。
⇒ **本设计必须把 `price_ratio is None` 当作一等公民**：结构位不可换算 ⇒ 走兜底（§6.2）。

### 4.5 `cpt_client` 的硬要求

- stdlib `urllib.request`，**超时 3s**（看板同机，慢就是不正常）；连接复用不做（v1 简单优先）。
- **绝不抛**：任何失败返回 `None` + 记 `log.warning`；`decide()` 必须能在 CPT 全挂时出结果。
- 只允许 `127.0.0.1` / `localhost`；目标 URL 由模块常量拼接，**不接受调用方传 host**。
- 结果**不缓存**（CPT 快照本身随行情变），但同一 `decide()` 内两个端点各只调一次。

### 5.2 逐函数签名（实现按此签名，不得随意改）

```python
# ── domain/holding.py ────────────────────────────────────────────────
@dataclass(frozen=True)
class Holding:            # 一笔在仓
    code: str
    entry_date: date
    cost: float
    shares: int
    note: str = ""

@dataclass(frozen=True)
class Levels:             # 价位（全部 raw 域）
    buy_reference: float | None
    stop_price: float | None
    target_price: float | None
    basis: str            # "cpt_structure" | "pct_fallback"
    detail: str           # 人读的来源说明，进 reasons

@dataclass(frozen=True)
```

### 5.3 `decide()` 的执行顺序（严格按此，便于单测逐段打桩）

1. 归一化 `code`（6 位、`zfill`、非数字 → 400）；解析 `as_of`（默认最新有 `daily_bar` 的交易日。
   **不用 `date.today()`**：非交易日/盘前拿不到当日 bar）。
2. 取行情：`stock_basic`（name/board/is_st/float_shares）→ `daily_bar`（当日 close/amount）
   → 无 bar ⇒ `ok=False, error="no_bar"`（**不猜价**）。
3. 取判据：`derived_bar`（当日行，可能缺）、`market_stat`（退潮/窗口）、`promotion_day`/`ladder_day`。
4. `cost/shares` 缺省时尝试从 `position` 表按 code 取在仓快照（`analyze_holdings` 场景）。
5. `use_cpt and cpt_enabled()`：`fetch_snapshot` → `overlays`；`fetch_recommendation` → `price_ratio`+结论。
   任一失败 ⇒ 记 `reasons[degrade]`，继续。
6. `levels = structure_levels(overlays, price_ratio, close=close)`。
7. `sizing = plan_shares(capital=capital, entry=levels.buy_reference or close,
   stop=levels.stop_price, amount=amount, board=board)`。
8. **方向判定**（纯优先级表，见 §7.2）→ `action`。
9. 生成 `ladder`（§7.3）、`reasons`、`facts`、`inputs`。
10. `persist and ok`：`upsert_decision(d)`。
11. 返回 `Decision`。

### 5.4 错误与降级契约（三档）

| 档 | 触发 | 输出 | `ok` |
|---|---|---|---|
| 甲 完整 | `overlays` 可用 且 `price_ratio` 有效 且 `capital` 有 | 结构位 + 绝对股数 | `True` |
| 乙 部分 | 上面任一项缺（CPT 挂 / `price_ratio=None` / 没给总资金） | 每一项**分别**降级并在 `reasons` 标注 `kind="degrade"` | `True` |
| 丙 不可用 | 无 `daily_bar` 行（未上市/停牌超窗） | `ok=False, error="no_bar"`，**不落库** | `False` |

HTTP 映射：`ok=True → 200`；`ok=False` 且 `error=="no_bar" → 404`（沿用 `/api/stock` 的
`200 if payload.get("ok") else 404`，`presentation/server.py:497`）；参数非法 → `400`。

## 6. 公式与口径（实现逐条对照）

### 6.1 价格域换算

```
raw = adj ÷ price_ratio        price_ratio = adj_close(最后一根) ÷ raw_close(同日)
price_ratio is None 或 <= 0  ⇒  结构位不可用（走兜底），不得回退成 1.0
```

### 6.2 价位（`levels.py`）

**结构位（`basis="cpt_structure"`）**——移植 CPT `application/track_points.py`，常数与算式逐条对齐：

| 量 | 算式 | CPT 出处 |
|---|---|---|
| 买参考 | `min(最近 2 个中枢.low ∪ 最近 3 笔中 direction==-1 的 .low) ÷ ratio × 1.02` | `track_points.py:182-221` |
| 卖参考 | `max(最近 2 个中枢.high ∪ 最近 3 笔中 direction==+1 的 .high) ÷ ratio × 0.97` | `:224-262` |
| 止损 | `买参考 × 0.95` | `:151-158` |
| 无候选 | 返回 `None` + `detail="无结构数据"` | `:203-208` |

**兜底（`basis="pct_fallback"`）**——只在结构位不可用时启用，`detail` 必须写明原因：

| 量 | 算式 |
|---|---|
| 买参考 | `close × (1 − FALLBACK_BUY_PCT)`，默认 `FALLBACK_BUY_PCT = 0.03` |
| 卖参考（=目标） | `close × (1 + FALLBACK_TARGET_PCT)`，默认 `0.05` |
| 止损 | `close × (1 − FALLBACK_STOP_PCT)`，默认 `0.08` |

> `close` 缺失（`no_bar`）时三个价位全 `None`，**不猜**。

### 6.3 数量（`sizing.py`，D1：固定风险 + 流动性上限，取小）

```
lot   = 200 if board == "star" else 100          # 科创板起购 200 股
R     = capital × RISK_PCT                        # 允许的最大亏损额，RISK_PCT=0.01
risk_shares = floor(R / (entry − stop) / lot) × lot         # entry>stop 才有效
liq_shares  = floor(amount × LIQ_PCT / entry / lot) × lot   # LIQ_PCT=0.01
max_shares  = floor(capital × MAX_POSITION_PCT / entry / lot) × lot   # 0.30
suggested   = min(risk_shares, liq_shares, max_shares)      # 存在的项才参与
position_pct = suggested × entry ÷ capital
```

**缺项处理（D2）**：

| 缺什么 | 结果 |
|---|---|
| `capital is None` | `suggested_shares=None`、`suggested_amount=None`；仍给 `position_pct = RISK_PCT ÷ ((entry−stop)/entry)`（风险反推的**上限**比例）；`method="risk_only_pct"`；`reasons` 加「未给总资金 → 只给比例」 |
| `stop is None` 或 `stop ≥ entry` | 风险法失效 → 只用流动性 + 单票上限；`method="liquidity_only"`；**明确标注**「无有效止损，无法按风险定仓」 |
| `amount is None` 或 `≤ 0` | 去掉流动性项；`method` 相应变化；标注「缺当日成交额」 |
| 有 `capital` 但 `stop` 与 `amount` **都**无效 | 只剩单票上限——它是**上限不是建议** ⇒ `suggested_shares=None`、`position_pct=None`、`method="maxpos_only"`，上限股数只写进 `detail`（否则等于凭总资金拍一个 30% 仓位） |
| `entry` 无效 | `method="none"`（HTTP 侧已 400；这是纯函数兜底） |

> 科创板精度说明：实际规则是「≥200 股起、之后可按 1 股递增」，本设计统一按 `lot=200` 向下取整
> （偏保守）。这是**已记录的近似**，不假装精确（**D9 已接受**）。

### 6.4 浮盈

```
pnl_pct = close ÷ cost − 1        cost 缺失 ⇒ None（不显示浮盈，不填 0）
```

### 6.5 边界（必须实现，必须测）

- `amount` 单位是**元**（`daily_bar.amount`），不是亿元；前端展示才除 `1e8`。
- `price_ratio` 必须 `> 0`，否则等同于 `None`。
- 分档价与股数：股数按 `lot` 取整后，**各档之和可能小于 `suggested_shares`**（取整损失），
  必须在 `ladder` 最后一档把差额补回去（保证 Σshares == suggested_shares）。这条**要有测试**。
- 停牌：`close` 可能为 0（实测有 8 只）。`close <= 0` 视作 `no_bar`（丙档）。
- `is_st=true`：`daily_bar` 涨停幅度是 5%（`derive.py:39 _pct_case` 只有板块口径，无 ST 分支
  —— 已知缺口）。本设计**不修**它，只在 `facts.is_st=true` 时给 `reasons` 加一条提醒。

### 7.2 方向判定优先级表（**纯确定性**，从上往下第一个命中即返回）

| 序 | 条件 | action | 标签 | 依据 |
|---|---|---|---|---|
| 1 | `market_stat.force_liquidate == true` | `EXIT` | 退潮清仓 | `exit.py:130` 同口径 |
| 2 | 有 `cost` 且 `close <= stop` | `EXIT` | 触及止损 | §6.2 |
| 3 | `derived_bar` 存在 且 `is_limit_up == false`（断板） | `TRIM` | 断板减仓 | `exit.py:130` |
| 4 | 有 `cost` 且 `close >= target` | `TRIM` | 到目标位减仓 | §6.2 |
| 5 | `derived_bar` 缺失（缺数） | `HOLD` | 缺数观察 | **F6：缺数不当作断板** |
| 6 | `dragon_env == "UNFAVORABLE"` 且 `buy_window == "NONE"` | `HOLD` | 环境不利 | `market_stat` |
| 7 | `cost` 缺失 且 现价 ≤ `buy_reference` | `ADD` | 未持仓·到买点 | 仅 `analyze_holdings` 以外场景 |
| 8 | 其余 | `HOLD` | 持有观察 | 默认 |

> 判据全部来自**已存在的确定性事实**，本层不引入任何新指标。`HOLD` 是默认而非兜底猜测。

### 7.3 分档规则（常数进 §8.2）

```
BUY 档  = [(buy_reference,        0.40), (buy_reference × 0.97, 0.35), (buy_reference × 0.94, 0.25)]
SELL 档 = [(target,               0.50), (target × 1.05,         0.50)]
去掉 price 为 None 的档；pct 归一化到 1.0；shares = 按 pct 分配 suggested_shares 并保证 Σ 相等（§6.5）
```

### 7.4 与执行契约的关系

沿用 `docs/16-Trade-API-Protocol.md` 的语义：`BUY ↔ OPEN_POS`、`SELL ↔ CLOSE_ALL`，
`buy_window` 是**买入口径的市场标签**，执行器不得以 `buy_window=NONE` 拒卖单。
**本设计不产出交易决策**（不改 `presentation/trade_api.py` 的 `volume: 100`，那是另一个工单）；
`holding_decision` 只作建议留痕。若要接执行器，是后续独立决策。

## 13. 风险与已知取舍（实施时必须原样保留在代码注释里）

1. **CPT `recommendation` GET 有写副作用**（§4.2）：稳态约每心跳每标的 1 行到 `cpt_recommendation`。
   **取舍：D8 已接受**（它是 CPT 自己设计的 GET 行为，且已内容去重+心跳）；提供 `--no-cpt` / `cpt=0` 关闭；
   主取数口仍用**只读**的 `snapshot`。若后续要求零副作用，改法是只用 `snapshot` + 自己按 §6.1 算倍率。
2. **结构位算式是「移植」不是「import」**（两侧契约禁止代码依赖）⇒ 存在漂移风险。
   对策：`levels.py` 的 docstring 逐条标注 CPT 出处行号；S2 单测用 CPT 的样例值做**固定断言**；
   若 CPT 改常数，需人工同步（已列入 `docs/15` 遗留）。
3. **CPT 无鉴权（回环直连）**：只允许 `127.0.0.1`，不接受外部 host（§4.5）。
4. **不给 `CONFIG` 加字段**（§1.3），否则全库策略指纹换代。
5. **`price_ratio=None` 是常态而非异常**（实测 `000002` 就是）⇒ 兜底路径必须有测试覆盖。
6. **`derived_bar` 自 2026-10-13 起不含 ST**（既定 A 方案）：ST 持仓的 `is_limit_up` 会缺行
   ⇒ 落到 §7.2 第 5 条 `HOLD` 缺数观察，这是**设计的必然结果**，不是 bug。
7. **不接执行器**：`volume: 100` 仍是写死的，本设计不改（§7.4）。
