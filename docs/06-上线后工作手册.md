## 0. 一分钟记住这个系统是什么

| | |
|---|---|
| 它是什么 | A 股市场情绪周期 · 盘后事实底座 · 决策系统 |
| 它不是什么 | **不是实时系统**，只做"T 日收盘后 → T+1 日参考" |

## 2. 每日运维（每个交易日盘后）

### 2.1 主流程

```
盘后（15:00 收盘后）
  ↓
1. 数据同步：拉当日全市场日线（东财主 + 新浪备）
  ↓
2. 计算判据：derived_bar（涨停/炸板/一字/换手/振幅）
  ↓
3. 情绪状态机：market_stat（4 相 + buy_window）
  ↓
4. 梯队与龙头：ladder_day / promotion_day
  ↓
5. 买入信号：signal（5 条件 checklist）
  ↓
6. 输出：日报 + 今日推荐（含打板价）+ 个股诊断
  ↓
7. 推送告警（webhook 三通道）
```

### 2.2 每日检查

- [ ] 今日 `daily_bar` 行数是否正常（约 **5,225 只**）
- [ ] `market_stat` 是否新增 1 行
- [ ] `signal` 是否有新增（多数日子为 0，正常）
- [ ] 日报 Markdown 是否生成
- [ ] 今日推荐是否给出（多数日子是"今天不买"）

### 2.3 备份策略

| 项目 | 频率 | 命令/方式 | 保留 |
|---|---|---|---|
| 全库 `pg_dump` | **每周一次** | `pg_dump --format=custom --compress=9` | 4 周 |
| 关键 CSV 导出 | 每月一次 | 导出 `market_stat` / `signal` | 长期 |
| 配置与代码 | 实时 | git push | 永久 |

**备份命令（注意角色和 SSL）：**
```bash
RDSHOST=$(sed -n 's/^\$RDSHOST=//p' ~/.dbconfig)
DB_PW=$(sed -n 's/^\$DB_PW=//p' ~/.dbconfig)
export PGPASSWORD="$DB_PW" PGHOST="$RDSHOST" PGUSER=postgres \
       PGSSLMODE=verify-full PGSSLROOTCERT=/home/ubuntu/global-bundle.pem
pg_dump --format=custom --compress=9 --file=backup_$(date +%Y%m%d).dump
```

## 5. 🚨 紧急回滚方案

如果新系统出问题，**立即回滚到 lkl + asel**：

```bash
# 1. 恢复服务
sudo systemctl enable --now lkl-daily.timer lkl-health.timer lkl-strategy.timer \
    lkl-dash.service asel-dash.service
sudo systemctl start lkl-close.timer lkl-trade.timer lkl-close.service lkl-trade.service

# 2. 恢复 asel 用户级服务
systemctl --user enable --now asel-backfill-daily.timer asel-production-daily.timer

# 3. 检查端口
ss -tlnp | grep -E '8098|8899'
```

**回滚是安全的**，因为：
- lkl 与 asel 的**单元文件都保留**（没删）
- 数据库数据**完整保留**（没删）
- 老仓库**还在**（`/home/ubuntu/DSH/longkonglong`、`/home/ubuntu/DSH/a_share_emotion_leader`）

**唯一的不可逆操作是删除老仓库** —— 在那之前，随时可以回滚。

## 6. ⚠️ 绝对不能做的事

1. **不要改奎爷的策略语义。** 任何"我觉得这里该改一下"的冲动，先问：
   这是奎爷的裁决，还是我的偏好？前者 → **别改**，只加注释标"存疑，待验证"。
2. **不要删老库的行。** 老库是唯一的对照基准。
3. **不要在 emotion-core 上线前删除 lkl / asel 仓库。** 那会让知识永久丢失。
4. **不要伪造日内精度。** 分钟线无源，算不出来的日内量不输出。
5. **不要在北交所数据上重算历史判定。** 会改 661 天历史数字，无法验证。

## 9. 故障手册（骨架，S10）

> 编码前先写 3 条最高频故障的处置，各 5 行以内。上线后再补。

### 9.1 东财 502 → 回退新浪

**症状**：daily 日志出现 `EastmoneyUnavailable` / 覆盖率门槛拒绝。
**处置**：自动回退新浪（逐股，~1h）。若新浪也失败，检查网络 + `~/.dbconfig`。
**预防**：东财对海外 IP 恒 502，回退是常态，不是异常。

### 9.2 覆盖率门槛拒绝装配

**症状**：日志 `coverage < 0.90, blocked`。
**处置**：检查 `asel.daily_bar_raw` 最新日期；手动跑 `backfill_history.py` 补数据；确认后重跑 daily。
**预防**：backfill 的 pgrep 守卫防双写；17:00 有重试 timer。

### 9.3 Wind 配额耗尽

**症状**：`theme` 步骤失败，日志 `QuotaError`。
**处置**：`NullThemeProvider` 自动降级（dragon_env 的 G2/B4 记 UNKNOWN），daily 链继续。
**预防**：配额账本（`ops_quota_ledger` 思想）在 `data/sync` 的 provider 层统一打点。
