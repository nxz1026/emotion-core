## C0 为什么只剩这条

B 轮把「追强族」三种入场（封板价、开盘价、回踩价）和「妖股回调 / 炸板次日 / 龙头断板」
全部证伪（见 ADR 0002 B 轮结论），情绪相位对宽基次日方向也没有预测力。
唯一为正的是全市场超跌均值回归（+0.50%/笔，n=20521），与本仓业务域无关。

⇒ 想要正期望，唯一剩下的可能性是**把决策移到盘中**：不是「盘后猜明天能不能封」，
而是「明天盘中看着封单决定要不要打」。这需要 C。

## C2 架构（三件套）

### ① 候选池扫描（盘中，不是盘后）

**修正**：C3 的结论是只做「首板 + 早盘封板」，而**首板在昨日梯队池里根本不存在**
（昨日 0 板 = 昨天没涨停）。所以池子不能由盘后产物预先给出，必须盘中从全市场扫：

- 扫描源：新浪 `Market_Center.getHQNodeData`（`node=hs_a`、`sort=changepercent&asc=0`、`num=100`），
  实测单请求即返涨幅榜顶部，含 `symbol/code/name/trade/changepercent/buy/sell/high/low/volume/ticktime`。
- 筛选：主板 7 前缀（`CONFIG.BOARD_PREFIXES`）、剔除 ST 与北交所、`changepercent >= 9.7`（10% 板）。
- 定板数：用上一次落库的 `derived_bar.cont_days`（T−1 日）判「首板」，**这是 ex-ante 字段**。
- 触发价：`limit_up_price_cents(pre_close_cents, code)`（T 日涨停价 = 今日 pre_close×板比，
  盘中可从五档的昨收字段得到），禁止 `*1.1`。
- 池子规模：涨幅 ≥9.7% 的主板票通常 5–40 只，单轮扫 1 请求 + 逐票五档 ≤ 40 请求。

### ② 盘中采集器（新，常驻）

- 交易时段（09:25–15:00）每 **30s** 一轮：
  1 次涨幅榜（上面那个接口）→ 命中票批量拉五档 `hq.sinajs.cn/list=...`（一次可带 30–50 只；
  新浪失败回退腾讯 `qt.gtimg.cn/q=...`）。
- 落新表 `intraday_quote(date, ts, code, price, bid1, bid1_vol, ask1, ask1_vol, chg_pct, at_limit)`，
  按 (date, code, ts) 主键；日增量 ≤ 40 只 × 660 轮 × 4 分钟粒度裁剪后约 1–2 万行。
- **不做**：不做 L2 撮合仿真（封单被扫无法模拟）、不做下单。

### ③ 触发 + 闭环

- 触发规则（初版，参数进模块常量，不进 `CONFIG.config_hash`）：
  `price >= 触发价` 且 `今日首封时刻 <= 10:00` 且 `昨日板数 == 0` 且
  `bid1_vol >= 阈值（初值 3 万手，需样本调）` 且连续 2 次采样成立 → 推「已封板」（附封单量）；
  随后若 `bid1_vol` 相对触发时衰减 > 70%，或价格 < 触发价 → 推「封单松动/破板」。
- 收盘回填：`derived_bar` 给出 `is_limit_up`（是否封到收盘）、`cont_days`；
  与 ADR 0002 同口径算 T+1/T+2 开盘收益，写 `trigger_outcome`。
- **定档门禁**：见 C4。在此之前产品面只说「已封板 + 封单 X 万手」，不给买卖指令。

## C3 已做的便宜实验：把「盘中打板」按真实成交口径算出来

探针 `_audit/probe_c_seal_quality.py`（只读，产物 `_audit/c_seal_quality.csv`）。
样本 = `limit_pool_em` 的 **ZT ∪ ZB** 两池（收盘封住 + 炸板，都有 `first_seal`），
2026-09-04~10-21 共 34 天，剔除一字板（`low == 涨停价`，封死后无对手盘）后 **n=1634 可成交**。
入场价 = T 日涨停价（`limit_up_price_cents`），卖点 = T+1 开盘（跌停封死顺延），费后双边 0.15%。

### 结论一：全样本仍然是负的，但结构是「双峰」

| 口径 | n | 每笔 | 胜率 |
|---|---|---|---|
| 全样本（涨停价买 → T+1 开盘卖） | 1634 | **−0.97%** | 39% |
| └ 封住到收盘 | 1146 (70.1%) | **+1.26%** | — |
| └ 炸板（持到 T+1 开） | 488 | −6.21% | — |
| └ 炸板（破板即当日卖，T 日收盘代理） | 488 | **−4.64%** | — |
| 组合（封住→T+1 开；破板→当日卖） | 1634 | −0.50% | — |

**盈亏平衡要求封住率 ≥ 78.6%，实际 70.1%** —— 差 ~9pp。这不是「没有 alpha」，
而是「alpha 全在封住的那一侧，而封住与否在买入时不可知」。C 的价值就是补这 9pp。

### 结论二：ex-ante 切片后，缺口收窄到 ~5pp

只有**买入时就能知道的字段**才能当过滤器。按昨日板数切（`derived_bar` 前一日 `cont_days`）：

| 片段（早盘 ≤10:00 首封） | n | 封住率 | 封住时 | 破板时 | 组合 | 盈亏平衡所需封住率 |
|---|---|---|---|---|---|---|
| 首板（昨日 0 板） | 567 | 65.6% | +1.89% | −4.71% | **−0.38%** | 71% |
| 二板（昨日 1 板） | 164 | 65.9% | +2.22% | −7.50% | −1.10% | 77% |
| 三板+（昨日 ≥2 板） | 100 | 69.0% | +1.35% | −8.52% | −1.71% | 86% |

⇒ **C 应只做「首板 + 早盘封板」**：离盈亏平衡只差 5.4pp 封住率。
封单量只要能把这 65.6% 抬到 71% 以上，这条线就是正的。

### 结论三：封板质量确有分辨力（但那是另一个视角）

按 `first_seal` 分档的**隔夜溢价**（T 收 → T+1 开，需 T 日收盘已持有）：
≤09:30 n=249 **+4.24%**/胜率 70%；09:30–10:00 +1.79%；10:00–11:00 +1.37%；
11:00–13:00 +0.69%；13:00–14:30 +0.75%；>14:30 n=35 **−1.15%**/20%。
按炸板次数：0 次 +2.43%、1 次 +1.86%、2 次 +1.22%、3+ 次 +0.34%。
⇒ 早封、不炸板的票隔夜溢价最强，**但这是「T 日收盘已持有」的视角，盘后无法执行**——
正是 C 要争取的那部分。

### 教训（第三次踩同一个坑）

`is_limit_up`（A 轮）、`is_exchange`（B 轮）、`cont_days`（本轮）都是**收盘后才知道的字段**，
拿它们当成交判据或分层维度，相当于偷看答案。
`cont_days` 尤其隐蔽：炸板股 `cont_days=0`，按它 groupby 会把所有炸板样本**静默归入 0 板组**
（pandas `groupby` 丢 NaN，东财 ZB 池该列全空），于是「1板 +1.90%、2板 +2.16%」全部是幸存者偏差。
ex-ante 可用的只有：昨日板数、首次封板时刻、封单量、开盘涨跌幅。

## D2 表 DDL

```sql
CREATE TABLE IF NOT EXISTS intraday_quote (
    date        date        NOT NULL,
    ts          time        NOT NULL,          -- 采样时刻（精度到秒，入库前截到分钟）
    code        text        NOT NULL,
    price       numeric(12,2),
    chg_pct     numeric(8,2),
    bid1        numeric(12,2),
    bid1_vol    bigint,                        -- 股（新浪单位），展示时 /100 成手
    ask1        numeric(12,2),
    ask1_vol    bigint,
    at_limit    boolean     NOT NULL DEFAULT false,
    src         text        NOT NULL,          -- 'sina' | 'tencent'
    PRIMARY KEY (date, code, ts)
);
CREATE INDEX IF NOT EXISTS idx_intraday_quote_code_date ON intraday_quote (code, date);

CREATE TABLE IF NOT EXISTS trigger_log (
    date           date     NOT NULL,
    code           text     NOT NULL,
    name           text,
    first_seal_ts  time,                       -- 首次触及涨停时刻
    trigger_price  numeric(12,2),              -- 涨停价（分算法算出）
    seal_bid1_vol  bigint,                     -- 触发时买一量（股）
    broke          boolean,                    -- 当天是否破板（收盘回填）
    broke_ts       time,                       -- 首次跌离涨停价的采样时刻
    closed_sealed  boolean,                    -- 是否封到收盘（derived_bar.is_limit_up）
    prev_days      integer,                    -- 昨日连板数（ex-ante，0=首板）
    entry_px       numeric(12,2),              -- = trigger_price（口径：触及即成交）
    exit_px        numeric(12,2),              -- T+1 开盘（跌停封死顺延 T+2）
    rolled         boolean,
    ret_pct        numeric(8,3),               -- 费后
    settled_at     timestamp,
    PRIMARY KEY (date, code)
);
```

> 采样削峰：同一分钟内同价同量不重复写（`ts` 截到分钟后 PK 冲突即跳过），
> 否则 40 只 × 660 轮会灌出无意义重复行。

## D3 常量（模块级 `Final`，**不进** `utils/config.py`）

| 常量 | 初值 | 依据 |
|---|---|---|
| `SCAN_INTERVAL_SEC` | 30 | 新浪/腾讯批量容忍度；更密无收益 |
| `CHG_PCT_MIN` | 9.7 | 10% 板取 9.7 留出计算误差（20%/30% 板另判） |
| `EARLY_SEAL_DEADLINE` | `time(10, 0)` | C3：≤10:00 封板首板是唯一近盈亏平衡片段 |
| `SEAL_BID1_VOL_MIN` | 30_000 手 | 待样本调；初值取 `海洋王` 实测 19.6 万手的一档门槛 |
| `SEAL_CONFIRM_TICKS` | 2 | 抗撤单抖动 |
| `SEAL_WEAKEN_RATIO` | 0.30 | 买一量衰减到触发时 30% 以下视为松动 |
| `MAX_WATCH_CODES` | 40 | 单轮五档请求数上限 |

改任一常量必须同步改本节表格（数字即口径）。

## D4 主循环（`--loop`）

```
每 SCAN_INTERVAL_SEC：
  if 不在 09:15–15:05：sleep 到下一交易时段（用 trade_calendar 判，非交易日直接退出）
  page = sina_quote.rank(changepercent, desc, num=100)        # 1 请求
  hits = [r for r in page if r.code 主板前缀 and r.chg_pct >= 9.7 and not ST]
  if not hits: continue
  quotes = sina_quote.five_levels([r.code for r in hits][:MAX_WATCH_CODES])  # 1 请求批量
  if 失败: quotes = tencent_quote.five_levels(...)             # 回退，src 记 'tencent'
  rows, triggers = intraday.derive(quotes, prev_days, now)     # 纯函数
  loader.insert_intraday_quotes(rows)                          # 幂等（PK 冲突跳过）
  for t in triggers: loader.upsert_trigger_log(t) + notify(若开关开)
```

`prev_days` 从 DB 一次性预加载（`SELECT code, cont_days FROM derived_bar WHERE date = 上一交易日`），
循环内只做内存查表。

## D5 触发与松动（`algorithms/intraday.py` 纯函数）

- `is_at_limit(price, pre_close, code)` → `price >= limit_up_price_cents(...)/100`（>= 容浮点误差）。
- `seal_hit(quote, prev_days, now)`：`at_limit` 且 `prev_days == 0` 且 `now <= EARLY_SEAL_DEADLINE`
  且 `bid1_vol >= SEAL_BID1_VOL_MIN*100`（股）且连续 `SEAL_CONFIRM_TICKS` 轮成立。
- `seal_weaken(quote, seal_bid1_vol)`：`price < 涨停价` 或 `bid1_vol <= seal_bid1_vol*SEAL_WEAKEN_RATIO`。
- 判定顺序与 `state.py` 同风格：先命中先生效，None 不参与比较（F6）。

## D6 收盘回填（`--settle`）

`python -m emotion_core.services.intraday_watch --settle --date YYYY-MM-DD --persist`

1. 读当日 `trigger_log`；
2. `derived_bar` 取 `is_limit_up` → `closed_sealed`、`is_bomb` → `broke`；
3. `daily_bar` 取 T+1 开盘（跌停封死顺延 T+2）→ `exit_px`、`ret_pct`（费 0.15%）；
4. 更新 `trigger_log`；挂到 `orchestration/daily.py` 尾部（每日一次，幂等）。
