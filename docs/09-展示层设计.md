## 0. 三原则的本质：**信息抽象层级**

你的三原则不是三个页面，而是**同一份数据的三个抽象层级**：

```
直观层  ←  决策语言    "今天买不买、买什么、为什么"
  ↑ 翻译
逻辑层  ←  市场事实    "炸板 5 只、最高 5 板、晋级率 42%"
  ↑ 计算
算法层  ←  计算口径    "炸板数 = derived_bar 中 is_bomb 行数；数据来自 daily_bar ← 东财/新浪"
```

**用户从直观层进入，有问题逐层下钻到算法层。** 这是正确的信息架构。

## 2. 三层架构设计

### 2.1 直观层（首页 `/`）

**目标**：30 秒读完当日结论。**通俗语言，不用术语**。

| 区块 | 内容 | 示例 |
|---|---|---|
| **今日结论** | 一句话 + 推荐 | **"今天不买。"** 原因：市场处于退潮期（历史上该状态下信号赔率为负）。有候选但被"淘汰性"拦下。 |
| **推荐股票** | 主推荐 + 次级推荐 | **002403** · 第 5 板 · 换手封板 · 满足全部 5 个条件 |
| **买点参考** | 打板价 + 赔率 | 打板价 = 昨收 × 1.1 = **12.85 元**；历史同状态 N=150：次日涨停率 42% |
| **"不买"的理由** | 多数日子必须给 | 今日次级观察：002403（第 3 板）—— 禁买日观察记录 |
| **市场情绪一句话** | 通俗描述 | 今天市场在**上升期**，历史上这种状态下信号次日平均高开 3.1% |
| **风险提示** | 固定显示 | ⚠️ **统计参考，非投资建议。** 历史 N=150，样本有限。 |
| **生态评级** | 通俗解释 | 当前环境：**一般**（G2）—— 龙头有高度但梯队不厚 |
| **加速事件预警** | 一字板扎堆 | ⚠️ 今日 3 只一字板，历史上这种状态下追高容易吃面 |
| **乱七八糟功能** | 入口集中 | [历史回放] [数据质量] [个股诊断] [研究栈] [参数配置] |

### 2.2 逻辑层（`/logic` 及子页）

**目标**：展示市场情绪的**参数**。用户提到的"炸板数、一字板"都在这层。

| 参数 | 值 | 说明 |
|---|---|---|
| 涨停家数 | 50 | 今日涨停的只数 |
| 炸板数 | 5 | 曾涨停但未封住的只数 |
| 跌停数 | 2 | 跌停只数 |
| 一字板数量 | 3 | 开盘即涨停、全天未开的只数 |
| 一字板占比 | 6% | 一字板 / 涨停家数 |
| 换手板数量 | 45 | 涨停且盘中打开过的只数 |
| 连板高度 | 5 | 最高板数 |
| 梯队分布 | 2板:8 / 3板:5 / 4板:2 / 5板:1 | 各板高度只数 |
| 唯一龙头 | 002403 | 唯一最高板 + 充分换手 |
| 晋级率（名义） | 42.3% | 含一字板的晋级率 |
| 晋级率（换手） | 25.7% | 可买到的晋级率 |
| 背离度 | 16.6% | 名义 − 换手 |
| 生态评级 | G2 | G1-G4/B1-B5 |
| 加速事件 | A1 命中 | 高度加速 |
| 题材热度 | TOP3: 机器人/AI/芯片 | theme_group |
| 人气榜 | TOP10 | hot_rank（东财独有） |
| 市场情绪走势 | 近 10 日折线 | phase/buy_window 时间线 |

### 2.3 算法层（`/algorithm` 及子页）

**目标**：展示**参数怎么算的、数据从哪来**。回答"为什么这个数字是 50 不是 48"。

| 区块 | 内容 |
|---|---|
| **计算公式** | 每个参数的 SQL/伪代码（如"炸板数 = `COUNT(*) WHERE is_bomb` FROM derived_bar"） |
| **数据来源** | 数据血缘（如"derived_bar ← daily_bar ← 东财 clist / 新浪"） |
| **样本量** | 每个统计带 N（如"晋级率基于 150 个历史信号"） |
| **数据质量** | 覆盖率、缺失天数、数据源状态（如"今日覆盖率 99.8%，缺 2026-09-22"） |
| **历史信号回放** | evaluate.py 的 forward_stats（次日高开分布、T+3/T+5 表现） |
| **次日验证** | 昨日预测 vs 今日实际（"昨日说今天允许买，今天实际是退潮期"） |
| **参数版本** | config.py 的阈值（MIN_LEADER_DAYS=4, CLIMAX_ZT=80...） |
| **口径裁决记录** | C1-C7 的裁决（为什么连板照 lkl、为什么北交所不参与判定） |

## 3. 补充：你可能没想到的展示数据

### 3.1 直观层补充

| 补充 | 为什么有用 |
|---|---|
| **样本量与置信度** | 每个统计带 N。"次日涨停率 42%（N=150）" vs "次日涨停率 42%" —— 前者让人知道可信度 |

## 4. 数据源裁决

### 4.1 原则：**只读 + 松耦合**（asel 方式）

| 维度 | 裁决 |
|---|---|
| 展示层**不写 DB** | 只读 |
| 展示层**不 import service** | 避免紧耦合 |
| 数据来源 | **直连 DB 只读**（不是快照文件） |

### 4.2 为什么直连 DB 而不是快照文件

| | 快照文件（asel） | 直连 DB 只读（推荐） |
|---|---|---|
| 数据新鲜度 | 快照时刻（每日一次） | **总是最新** |
| 可溯源 | ✅ 好 | 需要额外记录 |
| 部署复杂度 | 需要快照目录 | **简单（一个 DB 连接）** |
| 离线查看 | ✅ 可以 | ❌ 不行 |

**⇒ 推荐直连 DB 只读**。快照文件作为**每日存档**（可溯源），但展示层读 DB。

**理由**：展示层是"只读快照的独立 web"，直连 DB 最简单。快照文件是编排层的产物，不是展示层的必需。
