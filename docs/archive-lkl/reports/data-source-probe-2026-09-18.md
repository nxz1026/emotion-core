## 2. 确实拿不到（真缺口）

### 2.1 历史涨停池——东财只给近端

| 日期 | 结果 |
|---|---|
| 2026-09-17（近端） | **47 行** ✅ |
| 2026-09-16（近端） | **89 行** ✅ |
| 2025-06-27 | **0 行** ❌ |
| 2024-06-28 | **0 行** ❌ |
| 2019-06-28 | **0 行** ❌ |

→ 这解释了库里 `limit_pool_em` 只有 28 个交易日（2026-08-11 起）。
→ **影响**：封板时间 / 开板次数 / 分时走势历史**不可回溯**，只能自算或另找源。v1.0 §4 已把它列为"后续可选"——**这个判断是对的**。
→ 不影响第一期（v1.0 第一期字段表里没有封板时间）。

### 2.2 历史 ST 时段——免费源给不出日期

`ak.stock_info_change_name(symbol="600806")` → **9 行**，但列只有 `['index', 'name']`：

```
0  1  ST昆机
1  2  昆明机床
2  3  交大科技
3  4  S交科技
4  5  交大科技
5  6  昆明机床
6  7  *ST昆机
7  8  退市昆机
8  9  昆机5
```

**`index` 是序号，不是变更日期**——只能知道名称顺序，**无法重建"某日是否 ST"**。

→ 这是 v1.0 §4 标"**必需**"的一项（"历史 ST/退市整理/无涨跌幅限制状态"），**目前没有免费源**：
- Tushare `namechange` 有日期，但用户明确没有账户
- 逐日名称快照：没有历史
- 唯一替代：用 `is_st` 当前口径 + 显式标 `UNKNOWN`（v1.0 §4 的缺失处理要求"对应日期资格 UNKNOWN"）——**即诚实降级，不是伪造**
→ **这是 M0 必须报告的核心阻塞项。**

## 5. 陷阱记录

1. **"有接口" ≠ "现在能用"**：TDX 能连、能返回证券总数 27934，但 K 线请求全 0 根——**只测连通性会得出"源正常"的错误结论**，必须测到目标数据本身。
2. **同一源会间歇性可用**：东财日线第一次请求成功（600519/2019，118 行 1.1s），之后间隔 25s/40s 的连续请求全部 `RemoteDisconnected`。单次成功不能判定源可用，必须连续多次测。
3. **涨停池要区分"接口挂"和"历史无数据"**：近端（09-16/09-17）正常返回 47/89 行，历史（2019/2024/2025）返回 0 行——**同一函数、同样 0 行错误码，语义完全不同**。
4. **`stock_info_change_name` 看着像"历史 ST 源"，实际没有日期**：列名 `index` 是序号。差点误判成"历史 ST 可重建"。
5. **grep 过滤会吞掉探针输出**：腾讯源的 tqdm 进度条含 `it/s]`，我的 `grep -v "it/s]"` 把两条成功结果整行删了，一度以为腾讯源也失败。**过滤探针输出要按行号核对条数**。
6. **库里字段存在 ≠ 已填充**：`stock_basic.list_date` 列存在但 5,554 行全 NULL；`first_bar_date` 5,223 行有值。查覆盖率必须 `count(列)` 而不是看 `information_schema`。
