## 1. 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  展示层 presentation/        三层 web（直观/逻辑/算法）        │
├─────────────────────────────────────────────────────────────┤
│  编排层 orchestration/       linear daily.py + systemd       │
├─────────────────────────────────────────────────────────────┤
│  LLM 层 llm/                 抽象层 + Agnes（默认关）         │
├─────────────────────────────────────────────────────────────┤
│  数据层 data/                 DB 迁移 + 同步 + 清理           │
├─────────────────────────────────────────────────────────────┤
│  算法外壳 algorithms/         PyO3 绑定 + Python 接口        │
├─────────────────────────────────────────────────────────────┤
│  算法核心 core/ (Rust .so)    纯计算（判据/连板/状态机/信号） │
├─────────────────────────────────────────────────────────────┤
│  工具层 utils/                db / dates / price / config    │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向**：**自上而下**（展示层依赖编排层，编排层依赖数据层...）。
**禁止反向依赖**：算法核心不依赖 Python，Python 外壳不直接写 DB。

| `llm/*` | LLM 层 | 抽象层 + Agnes | ✅ |

### 2.2 模块间接口

**核心原则**：**模块间只通过明确接口通信，不直接访问内部状态**。

| 接口 | 调用方 | 被调用方 | 契约 |
|---|---|---|---|
| `compute_indicators(bars) -> derived` | `algorithms/indicators.py` | `core/indicators.rs` | 输入 `&[f64]`，输出数组 |
| `classify_states(derived) -> states` | `algorithms/state.py` | `core/state.rs` | 同上 |
| `compute_signals(...) -> signals` | `algorithms/entry.py` | `core/entry.rs` | 同上 |
| `sync_daily(date) -> coverage` | `orchestration/daily.py` | `data/sync.py` | 输入日期，输出覆盖率 |
| `cleanup(days) -> deleted` | `orchestration/daily.py` | `data/cleanup.py` | 输入保留天数，输出删除行数 |

## 3. 功能化设计

### 3.1 功能清单（按用户可感知的功能组织）

| 功能 | 模块 | 用户可感知 |
|---|---|---|
| 今日推荐 | `algorithms/entry.py` | 首页推荐股票 |
| 买点参考 | `algorithms/entry.py` + `utils/price.py` | 首页打板价 |
| 市场情绪 | `algorithms/state.py` | 首页情绪一句话 |
| 梯队展示 | `algorithms/ladder.py` | 逻辑层梯队 |
| 晋级率 | `algorithms/promotion.py` | 逻辑层晋级矩阵 |
| 生态评级 | `algorithms/ecosystem.py` | 逻辑层生态 |
| 个股诊断 | `algorithms/*` + `data/db.py` | `/stock/<code>` 页 |
| 数据质量 | `data/sync.py` | 算法层数据质量 |
| 历史回放 | `algorithms/entry.py` | 逻辑层历史信号 |
| LLM 解读 | `llm/base.py` | 直观层自然语言（默认关） |

### 3.2 每个功能独立测试

**每个功能必须有独立测试**，测试边界：
- **算法核心**：纯函数测试（输入固定 → 输出固定）
- **算法外壳**：集成测试（Python 调 Rust 结果正确）
- **数据层**：覆盖率测试（同步后覆盖率 ≥ 99%）
- **编排层**：端到端测试（全流程跑通）
- **展示层**：路由测试（HTTP 200 + 数据正确）
- **LLM 层**：mock 测试（prompt → 输出格式正确）

## 5. 依赖关系

```
utils（工具层）
  ↑
core（Rust 算法核心）—— 不依赖任何 Python 模块
  ↑
algorithms（Python 算法外壳）—— 只依赖 core + utils
  ↑
data（数据层）—— 依赖 algorithms（计算）+ utils（工具）
  ↑
orchestration（编排层）—— 依赖 data + algorithms + utils
  ↑
presentation（展示层）—— 依赖 orchestration + data + utils
  ↑
llm（LLM 层）—— 依赖 algorithms（可选）
```

**禁止**：
- core 反向依赖 algorithms/data
- presentation 直接写 DB
- 任何模块直接访问另一模块的内部状态
