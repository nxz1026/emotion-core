### 4.3 `suggested_points` 形状与五个价格槽

```jsonc
"suggested_points": {
  "buy":  {"reference": {"price_level": 3.59, "condition": "...", "rationale": "..."},
           "confirmed": null},
  "sell": {"reference": null, "confirmed": null},
  "stop_loss_reference": null
}
```

| 槽 | 算法（`cpt/application/track_points.py`） | 条件 |
|---|---|---|
| BUY reference | `min(近 2 中枢下沿 ∪ 近 3 向下笔低点) ÷ ratio × 1.02` | 候选非空 |
| BUY confirmed | `最新中枢下沿 ÷ ratio`（**0 缓冲**） | `status=="confirmed"` 且 action ∈ {buy, watch} |
| SELL reference | `max(近 2 中枢上沿 ∪ 近 3 向上笔高点) ÷ ratio × 0.97` | 候选非空 |
| SELL confirmed | `最新中枢上沿 ÷ ratio` | `status=="confirmed"` 且 action == sell |
| `stop_loss_reference` | `buy.reference × 0.95` | 见下 |

**两个隐藏门槛（必须知道，否则会误判为 bug）**：

1. **`price_ratio` 为空 ⇒ 五个槽全 null**（分支 A）。且分支 A 的返回**不带 `reason` 键** ⇒ 前端只能显示「—」。本轮 **S0** 修。
2. **`stop_loss_reference` 只在 track 条目的 `note` 含「长期」/`long`/`hold` 时才给**。倍数完整时止损仍可能是 null —— 这是设计（`track_points.py:151-158`），不是 bug；UI 要显示原因（「未标注长期持有」）。

### 4.4 按需补因子（D5 已具备，不需 CPT 改动）

`GET /api/dashboard/a-share/snapshot?code=X&ensure_factors=1` 会调
`FactorEnsurer.ensure(code)`（`cpt/adapters/a_share_factor.py:390`）现拉该 code 的因子并 upsert。

| `ensure_factors` | 语义 |
|---|---|
| `1` | **本条请求**显式要求补因子（用户主动输入 code）。**仍受 env `CPT_ASHARE_ONDEMAND_FACTOR` kill-switch 约束**（env 显式 `0/false/off` 时退化为只读） |
| `0` | 永不补，只读 |
| 省略 | 只有 env 显式开启才补（默认只读） |

- `ensure()` **绝不抛**；`FactorEnsureResult(code, fetched, rows, reason, detail)`，reason ∈ {unsupported, cooldown, empty, error, unavailable}。
- 有冷却（`DEFAULT_COOLDOWN_SECONDS`）与永久 `_unsupported` 缓存。
- **代价**：一次联网拉几百行，秒级。emotion 侧要给它**单独的更长超时**（§9）与**前端转圈 + 分步文案**（§10.3）。

### 4.5 门禁（决定「谁读谁的表」）

| 门禁 | 位置 | 影响 |
|---|---|---|
| 共享表契约测试 | CPT `tests/test_shared_tables_contract.py:150-183`（扫 `cpt/**/*.py` 的 `FROM/JOIN public.<t>`） | 任何让 CPT 读 emotion 表的写法**直接红** |
| SQL 分层 | CPT `scripts/check_sql_layering.py`（SQL 只准在 `adapters/`+`storage/`） | 同上 |
| 内部 import | CPT `.importlinter` | **只管内部 import，对 HTTP 出站无感** |

⇒ 结论：**CPT → emotion 方向的读被拦死；emotion → CPT 的 HTTP 路线不受影响**。这就是 N1 选「CPT 为真源 + emotion 走 HTTP」的技术根据。

### 4.6 用户身份

- CPT `cpt/web/track_api.py::extract_user_id(headers)`：读 `X-CPT-User`；缺失/空白/含非 `[A-Za-z0-9._-]` → `"default"`；截断 64 字符。**零校验**。
- CPT 前端存在 `localStorage["cpt_track_user"]`（正则 `/^[A-Za-z0-9._-]{1,32}$/`）。
- emotion 侧对齐：`localStorage["emotion.cptUser"]`，默认 `default`，同正则校验（§10.4）。

### C1 · 倍率配对放宽为「同日可配对」（D2 / C 方案的核心）

**文件**：`cpt/web/a_share_routes.py`（`build_recommendation` 内，约 `:251-260`）

**现状**：`_last_day == _raw_day` —— 要求「快照末根日 == `daily_bar` 的**最新**日」，否则 `price_ratio = None` ⇒ points 全 null。

**改法**：把「最新日」放宽为「**同日**」—— 用**快照末根那天**去 `daily_bar` 取同日收盘。

```
旧:  _raw, _raw_day = _raw_bar_for(code)                # daily_bar 最新一行
     if ... and _last_day == _raw_day: ratio = adj/_raw
新:  _raw, _raw_day = _raw_bar_for(code, on=_last_day)  # 指定日；缺该日 → None
     if ... and _raw_day == _last_day: ratio = adj/_raw  # 同日即可，不要求是最新
```

- 需要给 `_raw_bar_for` 加一个「指定交易日」的参数（默认仍取最新，向后兼容）。
- **零契约变更**（`overlays` 仍留 adj 域）、**零数据成本**。

**实测依据**（2026-10-14）：

```
daily_bar 每日 code 数：10-08 5223 / 10-09 5223 / 10-12 5223 / 10-13 5213
000002  快照末根 10-12 adj_close=1263.143，daily_bar 10-12 close=3.77
        → 同日倍率 335.051194
        → 中枢候选 [1251.07, 1179.86, 1183.98] → adj买点 1203.46 → raw 买点 3.59   ✅（改前全 null）
600519  快照末根 10-13 adj_close=8151.840，daily_bar 10-13 close=1274.89
        → 同日倍率 6.394152 → raw 买点 1374.12（与 CPT 自算 6.3942 一致）            ✅
```

- 000002 的中枢 1179.86 与它 `explain_algorithm.what_would_invalidate` 的「最近中枢下沿 1179.86（后复权）」**完全对上** ⇒ 结构本来算对了，只是没换算。

**「快照落后于行情」怎么办**：不由倍率承担 —— `data_quality` 的 `severity/gap/stale` 已在表达（emotion 侧 `cpt_client.data_quality_note()` 已消费）。

## 8. 公式与边界

### 8.1 价位（R3 已实现，本轮不改算式）

`src/emotion_core/algorithms/levels.py`：

```
basis = "cpt_structure"  （ratio 有效）
  买参考 = min(近 2 中枢 low ∪ 近 3 向下笔 low) ÷ ratio × 1.02
  止损   = 买参考 × 0.95
  目标   = max(近 2 中枢 high ∪ 近 3 向上笔 high) × 0.97
basis = "pct_fallback"   （ratio 无效，兜底）
  买参考 = close × 0.97   止损 = close × 0.92   目标 = close × 1.05
```

> ⚠️ **算式复制风险**：emotion 的 `levels.py` 是 CPT `track_points.py` 算式的**移植**（常量同值、注释直接指 CPT 行号），跨仓**没有门禁**。
> **本轮决定：保留（不删）** —— 它的 `pct_fallback` 正是 000002 唯一能出价的原因。
> **防漂移措施（S6 做）**：emotion 侧加一条测试，断言三个常量与 CPT 文档值一致，并在注释里钉住 CPT 的对应行号（已有）；CPT 侧若改算式，靠 `docs/18 §8.1` 的反向引用提醒。

### 8.2 数量（R3 已实现，本轮只参数化）

```
risk   = capital × risk_pct            ÷ (entry − stop)
liq    = amount  × liq_pct             ÷ entry
maxpos = capital × max_position_pct    ÷ entry
取三者的最小值 → 按手数向下取整（LOT_MAIN=100 / LOT_STAR=200）
```

- `entry` = **计划买点**（`Levels.buy_reference`），不是市价；缺则用当日 `close`。
- 只剩 maxpos 可用时**不给股数**（`method="maxpos_only"`，上限只写 `detail`）。

### 8.3 动作（R3 已实现，优先级不变）

`EXIT`（退潮 `force_liquidate`）> `EXIT`（断板）> `EXIT`（跌破止损）> `TRIM`（≥目标）> `ADD`（未持有且价 ≤ 买参考）> `HOLD`。
**CPT 结论只并排展示，不参与本层判定**（R3 D7 不变）。

### 8.4 参数边界（新增）

| 参数 | 默认 | 允许区间 | 越界行为 |
|---|---|---|---|
| `risk_pct` | 0.01 | 0.001 – 0.05 | 回落默认 + `reasons` 记一条 |
| `liq_pct` | 0.01 | 0.001 – 0.05 | 同上 |
| `max_position_pct` | 0.30 | 0.05 – 1.00 | 同上 |
| `lot` | 按 board | 100 / 200 | 非法 → 按 board |
