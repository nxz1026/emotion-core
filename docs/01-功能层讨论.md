## 0. 本轮要解决的一个前置歧义

**"市场情绪分析"这四个字，在两个仓库里指的不是同一件事。**

| | lkl | asel |
|---|---|---|
| 状态集合 | `冰点/发酵/高潮/退潮` | `hot/neutral/cold/unknown` |
| 判定结构 | **优先级规则链**（退潮>高潮>发酵>冰点，首个命中定相；无命中**延续昨日**） | **单变量阈值分档**（只看 `limit_up_count`） |
| 输出 | `buy_window`（NONE/STANDARD/ENHANCED）+ `force_liquidate` | 7 项指标 + `state` |
| 性质 | **交易决策**（能不能买、要不要清仓） | **事实摘要**（今天几档、趋势如何、缺多少数据） |
| 阈值 | `CLIMAX_COUNT=80` / `ICE_COUNT_MAX=40`（无版本号） | `hot_min=80`（巧合相同）/ `cold_max=20`（**不同**） |

asel 全库 `grep 退潮|高潮|发酵|冰点|buy_window|force_liquidate|neg_feelback|phase` = **0 命中**。

> **asel 的情绪层是 lkl 的高潮腿与冰点腿的一维近似，不是同一个东西。**
> 两者**不能互相替代**，也**不能同时对外输出"市场状态"**。
> 这是功能层必须先拍板的第一件事（见 §5 Q2）。

## 1. 粒度约定

为避免后面混用，本轮统一用四个词：

| 词 | 含义 | 例 |
|---|---|---|
| **功能域** | 一组相关能力的集合 | 情绪与结构判定 |
| **能力** | 一句可验收的话：给定输入 → 产出什么 | 给定交易日，输出 `phase` + `buy_window` |
| **产出** | 可被别的层消费的具体东西 | `market_stat` 一行 / 一份 JSON 快照 / 一个页面 |
| **消费者** | 谁用它 | 人（复盘者）/ 交易端 / 研究流程 / 下游算法 |

另需区分**已落地**（有数据或有页面）与**设计有但未落地**（表建了但 0 行、模块写了但零 import）。
后者**不能算作"已有能力"**——asel 里这类占了很大比例。

## 6. 需要你拍板的问题

**Q1（阻塞）· 系统的最终用户是谁？**
只有你本人 / 你 + 少数人 / 公开访问。
→ 决定 F4 展示层形态，也决定 F3 交易桥要不要保留多端语义（lkl 有 `trade-halt` 停机总闸 + 多用户交换文件，
这暗示它当前是**多用户**的）。

**Q2（阻塞）· "市场状态"对外只留一套，选哪套？**
(a) lkl 4 相状态机为决策权威，asel 的 3 档降级改名为"涨停热度档"（**我建议**）
(b) asel 3 档为准，lkl 状态机废弃
(c) 两套并存
→ 注意：asel 的 `state` 是它快照与页面的消费契约，改名会破页面。

**Q3 · lkl 的 11 项独有决策能力，是否有你想砍或重构的？**
特别想听你对这四项的判断（它们是"策略研究性"最强、也最可能想重做的）：
① 龙头淘汰赛 ② 生态评级 G1-G4/B1-B5 ③ 加速事件 A1-A3 ④ LLM 策略观察。

**Q4 · 交易桥在终态的地位？**
这是 lkl 最"重"的功能，asel 完全没有，且它引入了多用户/多端语义。
保留 / 简化 / 剥离到独立仓库？

**Q5 · 历史深度做到哪一年？**
asel 有 2010 起（4064 天），lkl 只有 2023-11 起（691 天）。
→ 若要做 2020 前，创业板 2020-08-24 改革等制度规则**必须**落地（asel 的 `ref_limit_rule` 设计正是为此）。
