## 0. 先说一个必须让你知道的结果

我用你朋友自己写的研究栈，重放了 2024-01-01 ~ 2026-09-24 全史（`evaluate.replay()`，
它调用的是**和实盘完全相同的** `entry.checklist`，`:45`）：

| 指标 | 数值 |
|---|---|
| 历史信号总数 | **172**（增强窗口 150 / 标准窗口 22）（2026-09-26 时点，历史口径；现状见 §3） |
| **次日开盘高开**（中位） | **+4.78%**（p25/p75 −0.23% / +9.93%，胜率 **71%**） |
| **规则化收益**（次日开盘买 / 断板开盘卖，**费后**） | **中位 −0.57%**，均值 −1.52%，**胜率 43%**，尾部 p10 **−19.07%** |

**把这两行放在一起读，就是你要的答案，也是最需要警惕的地方：**

> 信号**确实**能选出第二天会高开的票（71% 胜率，中位高开 +4.78%）。
> **但如果你在次日开盘买进去，你是亏钱的**（中位 −0.57%，胜率 43%）。
>
> 因为那个 +4.78% 的高开**就是你的买入成本，不是你的利润**。
> 你在别人已经赚完的位置进场，然后股票回落。

**这就是为什么你朋友把买点留给自己决定（D3）。** 不是他偷懒，是
**最简单的买点（次日开盘）在这套策略上是负期望的**。他的买点大概不是开盘价。

⇒ **所以"买点参考"这件事，不能简单做，也不能拍脑袋给一个价格。** 见 §2。

## 2. 需求 R1：具体推荐股票 + 买点参考

### 2.1 "推荐哪只"——已有答案

`entry.check_signal` 每天输出唯一龙头代码；V14 的**次级推荐**（放宽阈值，始终生成）另给一个。
**系统每天最多给 2 个代码。这部分不用做新功能，只需把输出做得看得懂。**

### 2.2 "什么价买"——必须做成"多口径赔率对照"，不能给单一价格

奎爷的研究栈已有全部零件（实测确认）：

| 函数 | 行号 | 作用 |
|---|---|---|
| `replay(start, end, min_days, as_of)` | `:21` | 用实盘同一套 checklist 重放全史，只读不写生产表（`:3`） |
| `forward_stats(sigs)` | `:87` | 前向表现：次日高开 / 次日涨停率 / 次日收盘溢价 / T+3、T+5 最大涨幅与回撤 |
| `distribution_stats(stats)` | `:139` | 分位数分布报告 |
| `window_compare(stats)` | `:392` | STANDARD vs ENHANCED 分层对比 |
| `baseline_sim(stats)` | `:419` | 参考基线（**开盘买 / 断板开盘卖 / 费后**）—— 上面 §0 的数字就来自它 |
| `exit_compare` / `exit_report` | `:304` / `:316` | 卖出方式对比 |

**实测分层对照**（`window_compare`）：

| 窗口 | 信号数 | 平均高开 | 晋级率 | T+3 均涨 | T+5 均回撤 |
|---|---|---|---|---|---|
| ENHANCED | 150 | 3.07% | **42.28%** | 15.54% | **−12.93%** |
| STANDARD | 22 | 4.20% | 40.91% | 17.26% | −10.94% |

**这两个窗口没有实质差别**——这是另一个值得注意的发现（奎爷 Q1 决策本意是区分它们）。

### 2.3 建议的做法：呈现多个买入口径的赔率，让你自己看

**不给"建议买价"，给"口径对照表"**：

```
2026-09-24 · 002403 · 增强窗口 · 第 5 板 · 换手封板
满足全部 5 个条件

【历史同状态样本】N = 150（增强窗口全部信号）
  次日开盘溢价：  中位 +4.78%   p25/p75 −0.23% / +9.93%
  次日继续涨停率：42.3%        （= 打板口径的核心赔率）
  T+5 最大回撤：  −12.93%       （最坏情况参考）

【买入口径对照】（这才是"买点"）
  口径 B · 次日打板买（昨收×1.1）   ← 主口径，可给确切价格
  口径 A · 次日开盘买，断板卖     中位 −0.57%   胜率 43%   ← 负期望对照
  口径 C · 次日回踩买（昨收×k）     k 待统计定
```

### 2.3.1 ★ 盘后约束决定了"哪个口径能给确切买点"

本系统**盘后运行**（奎爷 `PLAN.md:25` B 决策：不做实时）。这直接决定：

| 口径 | 价格表达式 | **T 日收盘时能否给出确切数字** | 是否符合策略本意 |
|---|---|---|---|
| A · 次日开盘买 | 次日开盘价 | ❌ **不可知**（只能给历史溢价分布当预期） | 否（`baseline_sim` 的口径演示） |
| **B · 次日打板买** | **T 日收盘价 × 1.1** | ✅ **完全可以**（涨停价收盘时就已确定） | ✅ **是**（`REQUIREMENTS.md:17`"打板买它"） |
| C · 次日回踩买 | T 日收盘价 × k | ✅ 可以 | 部分 |

**⇒ 口径 B（打板）是唯一既符合策略本意、又能在 T 日收盘时给出确切价格的买点口径。**
**⇒ 它就是你要的"具体买点"：`打板价 = T 日收盘价 × 1.1`，今天收盘就能算出确切数字。**

口径 A 根本给不出确切价格——它只能给"历史平均高开 +4.78%"作为**预期**，
而实测那正是**负期望**（§0）。

详见 `decisions/0001-盘后约束与买点口径.md`。

**口径 B/C 需要新增计算，但这属于"新增统计"而非"新增规则"** ——
奎爷的 `baseline_sim` 用的是"开盘买"，与策略本意的"打板买"口径不一致，
补算打板口径**不改动任何判定逻辑**。

> **实施状态（2026-10-21 复核后已撤销，见 `docs/decisions/0002`「复核」与「A 止血」）**：
> 口径 B 曾落地（`entry.buy_point()` + `plan_text()` 写进 `signal.reason` 与报告 ⓪⑥ 段），
> 但 `_audit/probe_fill.py` 复核发现其**成交假设不成立**——`probe_exec.py` 用「次日收盘
> 封住涨停」（`derived_bar.is_limit_up`）当「买到了」，是事后视角；真实打板在**触及涨停
> 那一刻**成交，之后炸板撤不回。改按「触及即成交」重算（同一批 375 个信号、同一买入价）：
> **每信号 −1.26%**、成交后 −2.01%、胜率 50%、最差 −34.03%；炸板桶 71 条均亏 15.04%。
> ⇒ **买点/卖点已从产品面移除**（A 止血）：报告只给「市场情绪 + 观察名单 + 次日验证点」，
> `signal.reason` 回 NULL，BUY 即时推送默认关闭，持仓观察视角不再给打板价。
> 口径 B 若还要用，必须等 B 轮找到「成交假设能触发」的新边缘。

### 2.4 输出必须是"平语言 + 经验赔率"

接手者看不懂 `phase=发酵 / buy_window=STANDARD / c3 淘汰性 PASS`。展示层必须翻译：

| ❌ 不要这样写 | ✅ 要这样写 |
|---|---|
| `phase=发酵, buy_window=STANDARD` | **今天市场在上升期**，历史上这种状态下信号次日平均高开 3.1% |
| `002403 为 sole_top, cont_days=5, is_exchange=True` | **002403 是今天的唯一龙头**（第 5 板，换手封板，盘中买得到） |
| `c1~c5 全 PASS` | **它满足全部 5 个条件** |
| `(无)` | **次日继续涨停的概率 42%（历史 150 个同类信号）** |
| `(无)` | **⚠️ 次日开盘买入历史上是负期望（中位 −0.57%，胜率 43%）** |

**这是展示层的核心新增职责**：把算法输出翻译成决策语言 + 赔率 + **风险提示**。

### 2.5 样本量纪律

1. **必须显示 N**，不能只给百分比；
2. **N < 30 时标注"样本不足"**，不给分位数；
3. 守奎爷 F6：**缺失不补零**；
4. 守奎爷 F1：*"回测结论必须显式标注周期覆盖不足一个完整长周期，不得外推为策略长期有效性"*；
5. 守奎爷 A4 **右删失防护**（实测已生效）：`T+5 前向窗口未满 1 条；T+3 前向窗口未满 1 条`已剔除。

## 4. 需求 R2：输入股票代码，用这套算法分析

### 4.1 已有基础（两侧各一半）

| 已有 | 位置 | 缺 |

**零件都在，缺一个端到端的"个股诊断"聚合。**

### 4.2 三段式输出设计

输入：股票代码（+ 可选日期）。

**A · 它现在是什么** — 连板数 / 换手板还是一字板 / 在梯队哪一层 / 是否唯一最高板 /
今日 5 条件逐项 `PASS/FAIL/UNKNOWN` + 通俗原因 / 当前相位与窗口（平语言）

**B · 它过去干过什么** — 历史上当过几次唯一最高板（日期列表）/ 每次之后的 T+1/T+3/T+5 表现 /
历史触发过的所有信号及结果 / 最常见的断板模式

**C · 用它赌值不值** — 所在梯队层晋级率（名义/换手双口径）+ `divergence` /
所在题材完整性 / 生态评级影响 / **同状态历史样本赔率**

**落地现状（2026-09-30）——已实现并接入页面**：`diagnose(code, as_of=None, *, stats=None) -> dict`
（`services/diagnose_service.py`），按 **A 现在 / B 过去 / C 值不值** 三段分层，顶层返回键
`code, as_of, technical, fundamental, market, A, B, C, note`；已接入 `/api/stock`（对应 payload 新增 **`diagnose`** 键，
既有键名全部不变），`/stock/<code>` 页渲染三张卡片（`#diagnose-a-card` / `#diagnose-b-card` / `#diagnose-c-card`，

## 5. 一个必须接受的事实：多数日子答案是"没有"

实测：

| 指标 | 数值 |
|---|---|
| `market_stat` 总天数 | **661** |
| 有候选（`has_candidate=true`） | **423**（64%） |
| **允许买**（`buy_window != NONE`） | **244**（37%）：高潮 216 + 发酵 28 |
| 退潮期 | 292 天（**全部禁买**） |
| 冰点期 | 20 天（**全部禁买**） |
| 每日"换手口径 ≥4 板"= 1 只的天数 | 218（唯一性条件只在这 218 天可能成立） |
| 历史信号（replay） | 172（≈ 每 4 个交易日 1 个）（2026-09-26 时点口径；现状见 §3） |

龙空龙的设计哲学就是 **"只在龙头唯一确立时买，其余时间空仓"**（`REQUIREMENTS.md:17-18`）。
所以**"具体推荐股票"在多数日子的正确答案就是"今天没有"**。

**这是策略特性，不是系统缺陷。** 展示层必须把"没有"讲清楚：

> **今天不买。** 原因：市场处于退潮期（历史上该状态下信号赔率为负）。
> 有候选但被第 3 条"淘汰性"拦下（昨日同身位对手还有 2 只没断）。
> 今日次级观察：002403（第 3 板）—— 禁买日观察记录，不构成买入指令。

## 6. 这两条需求反推：对下游各层的要求

### 6.1 算法层
- **原样保留** 5 条件判定与 replay/增量的重放一致性（奎爷 A1：两路径 diff=0）
- 新增（**只是聚合与统计，不改判定**）：
  - 按窗口分层的次日开盘溢价分布
  - **打板口径（口径 B）与回踩口径（口径 C）的赔率** ← 新增，需确认
  - 按代码的历史身份与前向表现聚合

### 6.2 数据层
- **`pre_close` 必须存列**：除权日 `LAG(close)` 实测错 **339/192,593 行**（最大偏差 15.36 元）
  → 会让"次日开盘溢价"和"涨停判定"都算错
- **必须回填历史信号**（§3；2026-09-26 时点 replay 预估 172 个，2026-09-30 实测已回填 162 行、全部 `source='replay'`）
- **历史深度**：个股"历史身份"需要长回看 → 倾向 asel 的 2010 起。
  但注意奎爷 D6 决策 `DATA_START=2024-01-01` 是**判定口径**，**不能动**；
  深历史只用于**展示与统计**
- 需要**按代码快速查**（索引 / 物化视图）

### 6.3 展示层（最后定，但需求已明确）
- 核心职责：**把算法输出翻译成平语言 + 经验赔率 + 样本量 + 风险提示**

## 9. R3（2026-10-13 新需求）：输入我的持仓（成本价 + 数量）→ 输出 buy/sell 的**价格 + 数量**

> 奎爷原话（2026-10-13）：emotion + cpt「其实是可以做到对 A 股指定股票价格级的决策推荐的」，
> 但「实际情况是我买的股票和推荐的并不一样」，希望「输入我指定的股票后能分析（已有功能），
> 再加上我购买的单价和数量，通过已有的算法给出我 buy or sell 的价格 + 数量」。
>
> 本节是**只读调研**（2026-10-13，未改任何代码/数据），按 现状 → 缺口 → 方案 → 待拍板 四段。

### 9.1 一句话结论

**做得到，零件比预想的全** —— 但**两侧算法里都没有「数量」这个量纲**：现有输出恒为
「方向 + 一个价格」，没有股数/仓位，也不吃用户成本。必须新增一层
**「持仓决策包装」**（价格分档 + 数量口径），**不改任何现有判定逻辑（entry/exit 五条件、
CPT 一买一卖状态机都不动）**，并给接口加一组持仓参数。

### 9.3 缺口（7 条，全部实测）

1. **无数量量纲**。全 `src/` grep `sizing`/`position_size` 零命中；「仓位」二字只出现在
   `llm/strategies/*.yaml` 的**提示词正文**里（如 `chan_theory.yaml:41` 教 LLM 说
   「日线级别 30-50% 仓位」）—— 那是自然语言，**没有任何确定性代码消费它**。
   **CPT 侧同样零命中**（`position|仓位|股数|手数|quantity|sizing|kelly|lot_size` 扫描），
   唯一数量是 `web/trade_api.py:97 DEFAULT_VOLUME = 100` 常量。两侧那个 `100` 都是写死的。
2. **无资金/账户概念**。`utils/config.py` 无任何资金/风险参数；`position` 表也无账户维度
   （单账户假设）。⇒ 在拿到「总资金」之前，**给不出绝对股数**，只能给比例。
3. **价格单点化**。§2.3.1 拍板的三个口径里只实现了 B（打板价）；
   **口径 C（回踩价 `昨收 × k`）在 §7 N1 明确「要算」但至今未实现**
   （`_buy_point_reference` 只返回 `limit_price` 一个价）。
4. **持仓不参与决策**。`exit._open_positions()` 只 `SELECT code, entry_date`
   ⇒ 算不出浮盈、算不出「该减多少股」，也无法做移动止损。
5. **无分档**。没有「≤ x 价买 N 股 / ≥ y 价卖 M 股」这种阶梯结构，两侧都是单点信号。
6. **冲突裁决明确不设计**。CPT 盘中机会 vs emotion-core `buy_window=NONE` 禁买，
   ADR 0001 D4 写着「明确不设计」（CPT `shared-tables-contract.md` §5 再次确认）。
   ⇒ 要真正融合两侧信号，**这一步绕不过去，必须先拍板**。
7. **「缠论」同名不同物**：emotion-core 的缠论是**喂 LLM 的提示词**
   （`llm/strategies/chan_theory.yaml`），`algorithms/` 里没有分型/笔/中枢的确定性计算；
   CPT 才有。⇒ 只能走**数据 / HTTP 接缝**，「合成一个仓」已被 CPT 文档否掉。
   另：`signal` 表 162 行**全部 `source='replay'`、live=0** ⇒ 个性化决策目前没有实盘反馈样本。

### 9.4 可行方案（三档，从轻到重）

**方案 1 · 持仓决策包装（建议先做，预估 1–2 天）**
- 新增 `services/holding_service.py`：纯函数 `decide(code, cost, shares, *, capital=None, as_of=None) -> dict`
  —— **只读**现有表，**不改 entry/exit/CPT 任何判定**。
- 输出结构（草案）：
  ```
  {code, name, 我的成本/数量/浮盈%,
   action: "BUY_MORE"|"HOLD"|"TRIM"|"EXIT",
   ladder: [ {price, pct, shares, why} ],       ← 分档价+量
   stop: {price, basis},  target: [{price, basis}],
   odds: {...同 diagnose _seg_c...},  disclaimers: [...]}
  ```
- 价格口径候选（复用什么都不用现造）：买 = 打板价（已实现）/ 回踩价（补口径 C）/
  CPT 一买触发价；卖 = 断板价 / 前低 / MA20 / 固定百分比。
- 数量口径三选一（见 N8）：固定风险预算法 / 固定比例法 / **流动性上限**
  （`amount` 中位仅 **1.07 亿**，龙头 4.87–19.97 亿 ⇒ 小票的成交额是真约束）。
- 入口：先给 CLI + `GET /api/stock` 的可选参数（`cost`/`shares`），面板后置。
- **CPT 侧复用（走 HTTP，不引代码依赖 —— 两侧契约明令零 import）**：
  `GET /api/dashboard/a-share/recommendation?code=` 拿状态机结论 + 一买三事实（可解释依据）；
  `GET …/track/{code}/advice` 的 `suggested_points` 拿中枢/笔位参考价与**止损 ×0.95**。
  ⚠️ `price_ratio=None` 时这些字段是 null（实测 `000002`），N10 的兜底分支必须接住。

**方案 2 · 让 exit 读持仓（+1 天）**
- `exit._open_positions()` 扩列到 `entry_price, shares`；输出「浮盈 x% → 建议减 N 股」，
  并在 `exec_hint` 之外新增 `volume`。交易桥的 `volume: 100` 改为按持仓算。

**方案 3 · 两侧信号真正融合（大，需先拍板 N11）**
- 建统一 `decision` 表 + 冲突裁决规则 + 面板页；CPT 侧通过 HTTP 提供结构/背驰事实。
- **前置条件**：ADR 0001 D4 的冲突裁决必须先定；否则做出来的是两套并排而不是一套融合。

### 9.6 附录：CPT 侧链路事实（2026-10-13 只读深挖）

`has_two_centers = len(centers) >= 2`；背驰段 = 中枢二结束后仍向下的第一笔；
`has_reversal_bi = any(bi.direction != _DOWN for bi in level_bis[leg_index + 1:])`。

**4 档动作的映射**（`recommendation.py:47-57` + `:65-71 _STATUS_RANK` + `:159-170`）：
`confirmed → buy/sell`；`structure_ready → watch` +「结构已具备（待反向笔确认）」；
`candidate → watch`；`invalidated → hold`（再细分「结构条件不成立」vs「信号已失效」）。
**`alert` / `candidate` 当前不可达**（缺盘中数据）。

**参考价位**（`application/track_points.py`）：
- 买点 `_buy_reference(:182)`：候选 = 最近 2 个中枢下沿 + 最近 3 笔中向下笔的低点 → 取**最低**
